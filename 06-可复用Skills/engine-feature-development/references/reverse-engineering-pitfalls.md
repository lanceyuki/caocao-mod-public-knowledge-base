# 二进制引擎开发中的可复用教训

这些规则来自反汇编、功能移植、注入和故障定位实践。它们是分析方法，不是任何特定引擎的地址表或兼容性保证。

## 静态分析与移植

### 把参考实现当作假设

跨构建比较时，逐项核对目标函数边界、调用目标、门控、共享状态、数据表和调用约定。地址相同、函数名相似或行为目的相同，都不能独立证明实现等价。

### 线性反汇编需要边界佐证

代码和内嵌数据混排时，线性扫描可能从数据中间开始解码并失去同步。结合函数入口、控制流、原始字节调用目标和其他交叉引用确认边界；对节或区间遍历抽查已知位置，避免搜索脚本漏掉整段。

### 追到结果消费者

不要只停在属性读取、参数传入、辅助函数返回或某个条件跳转。继续检查后续选择、修饰、写入、返回和实际消费位置；区分对象字段、临时栈值、共享状态和最终效果。

### 调用约定要从机器码确认

检查每个相关调用的压栈顺序、寄存器输入、返回分支以及函数如何清栈。`ret`、带立即数的 `ret` 和被调用代码对寄存器/标志位的改写会影响后续控制流。只凭函数名或一次运行快照不够。

## 补丁和控制流

### 空闲空间要连同边界和引用一起检查

写入前检查整个候选区域、结束边界之外的指令、相邻数据和对该区域的引用。全零字节和 NOP 填充都可能处于活跃布局或被其他逻辑依赖；另需按最终生成长度确认各块互不重叠。

### 逐路径推演 Hook 和续接

至少分别推演命中、未命中、提前返回和原生门控分支。明确每个分支的栈高度、返回地址、寄存器和标志位。需要改变返回路线时，由一个有明确边界的桥接层拥有其临时栈帧，并证明返回时恢复了原调用契约。

### 完整迁移数据，不按可见样本截断

迁移查表逻辑前，先确定输入的完整值域和终止规则，再转储并比较完整数据范围。只保留当前可见样本或少数常用索引，可能让边界外行为静默失效。

### 检查整数宽度和符号扩展

把循环上限、索引和立即数转换成机器码语义再验证。确认有符号/无符号比较、操作数宽度、符号扩展及计数器终止条件，并模拟首项、末项和越界情况。

### 生成长度变化后重做布局

以最终机器码长度计算 `[start, end)` 区间。每次改动后重新检查边界、重叠、分支目标和完整反汇编；设计阶段估计的长度不是布局证明。

### 生成器应保护目标文件

把预期原字节、输出范围、表长度、模块边界和目标类型写成可自动检查的断言。正式产物、验证器和回滚应从同一数据源生成，并验证最终导出内容，而不只验证中间对象。

### 写入路径检查要早于临时文件和强制覆盖

先解析规范化后的输入和输出路径，再创建目录或写临时文件。拒绝输出与目标引擎、原始基线或其他受保护输入相同；调用方提供“强制覆盖”选项也不能绕过此保护。

### 有副作用的测试先隔离

测试历史生成器、注入器、迁移器或清理入口前，先静态检查其文件、进程、网络和调试器写入。红灯阶段优先用 mock、临时副本或子进程隔离；避免测试本身真实改写目标或运行中的进程。

### 数据布局由生产端和消费端共同定义

扩展缓冲容量、增加表项或搬迁结构时，同时核对初始化/生产循环、容量和尺寸描述、索引映射与最终消费者读取长度。只扩容存储区可能消除越界，却留下未初始化数据或缺失的新表项。

### 数字常量先查平台定义

遇到窗口消息、标志或 API 数字时，先查对应平台的公开常量定义，再沿处理分支确认实际语义。常量落在熟悉的数值范围，不足以证明它是引擎自定义协议。

## 动态观察与验收

### 函数职责不等于原生必经路径

即使一个 helper 的行为与目标功能完全吻合，也要查看目标调用者、所有路径和触发条件。分别记录“函数做什么”“原生流程何时调用它”和“新逻辑能否安全复用它”。

### 一次断点命中只证明到达该处

断点可能位于发出动作、选择目标、应用结果或更新画面之前。根据所要证明的事件放置观察点，继续追踪到对应消费者或状态变化，并区分动态执行证据与游戏内结果。

### 验收结果按层级报告

代码生成、磁盘写入、运行时读回、受控启动、调用路径观察和游戏内效果是不同结果。每项结论只声称已经观察到的层级；在目标动作发生前命中，不代表该动作已完成。

### 集成测试跟随真实集成风险

分别验证的改动在组合时，优先检查共享地址、共用调用链、状态交互和集成操作实际改变的行为。若集成没有改变某功能的代码或调用路径，不要把未执行的全量游戏矩阵写成已验收；也不要把单项通过外推为组合通过。

### 失败现场先于修复

崩溃或异常后，先保留可复现状态、调用栈、寄存器、改动范围和相关字节。以证据区分错误假设、边界覆盖、ABI、路径遗漏和数据差异，再做最小修正。
