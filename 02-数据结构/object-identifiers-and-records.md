# 对象类型与编号转换（6.5pl 样本）

> **样本范围：** 本页只说明一个 6.5pl 样本中用于理解攻击侧取值链的对象区别和编号转换。地址、步长和偏移只作复查线索；其他构建须在自己的目标上重新定位。本文不是完整结构体定义。

## 先分清对象

| 对象 | 用途 | 与编号的关系 |
|---|---|---|
| 战术单位（`TacticalUnit`） | 战场上的运行时状态，例如当前 HP、MP 和属性状态档位 | 由本场战斗的战场编号定位；`+0x00` 保存关联的 Data 号 |
| 角色数据（`CharacterData`） | 角色配置，例如装备和个人特技 | 由 Data 号定位 |
| Data 记录（`DataRecord`） | 原始属性及相关培养数据 | 也由 Data 号关联，但它与 `CharacterData` 是不同记录 |
| 物理攻击事务区 | 部分攻击路径中的临时编号、指针和结算结果 | 当前样本若干路径使用事务区 `0x4927F0`；内容须结合具体调用阶段解释 |
| 调用帧局部值 | 某次函数调用中的中间计算结果 | 由当前栈帧访问；不是战术单位或数据记录的持久字段 |

战场编号和 Data 号不是同一套编号。常见关系是：战场编号先找到 `TacticalUnit`，再从该对象读取 Data 号；同一 Data 号可以分别用于查找 `CharacterData` 和 `DataRecord`。

## 样本中的换算线索

| 输入 | 样本路径 | 样本计算关系 | 边界 |
|---|---|---|---|
| 战场编号 | `0x4061F9` | `TacticalUnit* = 0x4A7B20 + 编号 × 0x30` | 这是战术单位数组；换算函数本身不等于范围检查 |
| Data 号 | `0x484002` | `CharacterData* = 0x4A3E77 + Data号 × 0x61` | 这是角色配置记录，不是下方的 Data 记录 |
| Data 号 | 普通攻击属性链中的 `0x40658F → 0x4061E4` | `DataRecord* = [0x4CEA00] + Data号 × 0x48` | 这是原始属性记录；基址取自样本中的指针 |

这些绝对地址与步长只描述该样本。不要把它们当成稳定 ABI、跨版本接口或可直接写入补丁的地址。

## 物理攻击事务区

当前样本的部分物理攻击路径使用事务区 `0x4927F0`。其头部可同时保存战场编号、Data 号以及 `DataRecord`、`TacticalUnit` 指针；它是攻击流程中的另一类数据区，不等同于任一角色记录。字段会由具体路径初始化、更新或复用，不能假定所有调用点看到的阶段内容相同。

在一个样本初始化路径 `0x406232` 中，头部字段关系如下：

| 事务区偏移 | 该路径中的值 | 解释边界 |
|---|---|---|
| `+0x00` | 1-byte 战场编号 | 该路径中用作攻击方编号 |
| `+0x01` | 1-byte 战场编号 | 该路径中用作当前目标编号 |
| `+0x04` | dword Data 号 | 从攻击方战术单位取得 |
| `+0x08` | dword 指针 | 指向攻击方 `DataRecord`，由 `0x4061E4(Data号)` 取得 |
| `+0x0C` | dword 指针 | 指向攻击方 `TacticalUnit`，由 `0x4061F9(战场编号)` 取得 |

这张表只描述该初始化路径的字段来源。分析其他入口或后续结算阶段时，仍须追踪字段的重新写入和实际消费者。

候选页[暴击检定通过标记](../03-机制详解/critical-check-marker.md)只讨论该样本事务区 `+0x604` 的有限语义。它不提供事务区完整结构，也不把该字段等同于最终伤害或画面暴击结果。

## 与攻击侧分析相关的字段

- `TacticalUnit+0x00`：dword Data 号。
- `TacticalUnit+0x04`：打包字段；一个运行样本的低字节与战场编号相符。其余字节及跨场景含义没有在本页定义。
- `TacticalUnit+0x14`：当前 MP 的 dword 字段。样本函数 `0x472840` 通过 `word [unit+0x14]` 读取低 16 位；**读取宽度不代表字段宽度**。
- `TacticalUnit+0x18`：攻击属性状态档位；样本正常值为 `3`。它不是攻击力总值。
- `DataRecord+0x11`：索引 0 的 word 原始攻击属性，是攻击侧计算链的输入之一，不是最终攻击侧值。
- `[ebp-0x20]`：一个普通物理攻击调用路径中的调用帧局部值；它是后续修饰后的攻击侧结果，不是 `TacticalUnit` 的字段。

`TacticalUnit+0x1E` 是异常状态组字段，与 `+0x18` 起的属性状态档位属于不同用途。字段宽度、读取宽度和调用帧偏移应分别按各自消费者确认。

## 复核顺序

1. 先从寄存器或栈参数追出当前指针由谁产生，确认它指向哪类对象。
2. 沿编号转换函数核对目标基址、步长和编号来源；不要仅凭字段名认定对象类型。
3. 对每个偏移同时检查读写宽度和实际消费者。单次 `word` 读取不能证明字段只有 16 位。
4. 把结构字段与 `[ebp-N]` 等调用帧局部量分开；局部值只有在观察到明确写回和后续读取时才能称为持久字段。
5. 在自己的目标文件上重新确认指令、对象布局和控制流，再决定是否可复用。

本页的对象关系和换算式来自样本静态分析；有限运行时读回只支持其中明确标出的样本关联。它不证明完整结构、其他调用路径或其他引擎具有相同布局。
