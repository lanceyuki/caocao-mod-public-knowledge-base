# 如何追踪 Win32 控件的点击与文本刷新

这篇方法页帮助你从一个可见控件追到它的输入处理或文本更新路径。它面向经典 Win32 窗口，也提醒你把标准对话框、框架分发和自绘界面分开判断。页面描述分析方法，不代表任何特定游戏样本已经通过动态验证。

## 先确定你要追踪的行为

同一个可见控件可能接收输入、显示动态文字，或只改变启用和绘制状态。先写清楚你观察到的动作和结果，再选对应的代码路径。

- **点击或键盘操作**：追踪输入消息、控件通知和父窗口分发。
- **文字变化**：追踪刷新触发点、文本来源和写入控件的调用。
- **颜色、可见性或启用状态变化**：追踪状态设置和绘制路径。

截图中的标签只能帮助你找到线索。它不能单独证明控件编号、父窗口或处理函数。

## 确认控件身份和对话框路径

先确定目标控件属于哪个窗口、使用什么控件类型，以及程序如何创建它。不要把资源编号、控件编号和运行时窗口句柄当作同一个值。

1. 记录窗口标题、控件可见文字、控件类型、父窗口和触发步骤。注明你希望追踪点击、文字更新还是状态变化。
2. 检查可执行文件的对话框资源。如果找到模板，记录模板中的控件类、初始文字和控件标识符，再追踪创建该对话框的代码。
3. 对标准 Win32 对话框，模板描述布局和控件；创建函数另行接收对话框过程回调。沿 `DialogBoxParam`、`CreateDialogParam` 或间接创建路径确认回调地址。微软文档说明，对话框模板可来自资源或内存，应用程序还须提供对话框过程。[关于对话框](https://learn.microsoft.com/zh-cn/windows/win32/dlgbox/about-dialog-boxes) · [DialogBoxParamA](https://learn.microsoft.com/zh-cn/windows/win32/api/winuser/nf-winuser-dialogboxparama)
4. 如果资源中没有模板，继续检查内存模板、运行时创建的子窗口、注册窗口类和框架回调。没有资源模板不能单独证明界面是自绘的。
5. 区分模板中的控件标识符与运行时 `HWND`（窗口句柄）。句柄会在运行时创建；标识符用于把控件和父窗口收到的通知联系起来。
6. 如果检查器显示 `-1` 或空编号，先核对控件类、模板内容和运行时父子关系。静态控件可以设置 `SS_NOTIFY` 样式，并通过 `WM_COMMAND` 发送 `STN_CLICKED` 等通知；先确认样式，再判断它是否接收点击。[静态控件样式](https://learn.microsoft.com/zh-cn/windows/win32/controls/static-control-styles) · [STN_CLICKED](https://learn.microsoft.com/en-us/windows/win32/controls/stn-clicked)

同一段文字可能出现在多个窗口、格式串或数据表中。列出所有匹配项，按父窗口、引用路径和运行时上下文筛选，不要把第一个命中当作目标实例。

## 追踪点击和输入分发

标准对话框中的按钮操作可从对话框过程的消息分支开始，但其他控件和框架可能使用不同消息或回调。

1. 在创建路径中找对话框过程，或在窗口类注册和创建路径中找窗口过程。
2. 沿消息分发查找 `WM_COMMAND`、`WM_NOTIFY`、窗口专用消息或框架回调。
3. 对 `WM_COMMAND` 控件通知，核对 `LOWORD(wParam)` 中的控件标识符、`HIWORD(wParam)` 中的通知码，以及 `lParam` 中的控件窗口句柄。带 `SS_NOTIFY` 样式的静态控件也会发送点击通知。菜单命令和加速键使用相同消息，但参数含义不同；按微软消息定义区分来源。[WM_COMMAND](https://learn.microsoft.com/zh-cn/windows/win32/menurc/wm-command) · [静态控件样式](https://learn.microsoft.com/zh-cn/windows/win32/controls/static-control-styles)
4. 沿分支、跳转表或间接调用追到实际动作。记录条件门控、后续调用和可观察结果，不要把消息入口直接称为最终处理函数。
5. 如果界面自绘，追踪鼠标命中测试、键盘输入和动作分派。此时可见区域未必对应标准子窗口或控件标识符。

可用下面的链路记录标准控件的静态候选路径：

```text
父窗口或对话框过程
  → 消息类型与来源
  → 控件标识符和通知码
  → 分发分支或回调
  → 实际动作
  → 可观察结果
```

## 追踪文字刷新和状态变化

显示文字的路径与点击处理路径分开分析。静态文本可能由父窗口在刷新时更新，也可能由控件自行绘制。

1. 找到界面刷新触发点，例如选择变化、窗口打开或状态更新。
2. 沿调用和数据引用追踪文本来源，包括常量、字符串表、格式化参数和运行时生成值。
3. 检查 `SetDlgItemText`、`SetWindowText`、`WM_SETTEXT` 或框架对应接口，并确认目标窗口和控件身份。`SetDlgItemText` 会设置指定对话框控件的文字。[SetDlgItemTextA](https://learn.microsoft.com/zh-cn/windows/win32/api/winuser/nf-winuser-setdlgitemtexta)
4. 如果没有文字设置调用，检查自绘、所有者绘制和缓冲区更新路径。
5. 对颜色、可见性或启用状态，追踪状态写入及其最终绘制或输入效果；不要仅凭 API 名称推断屏幕表现。

如果控件只是显示文字，寻找它的点击分发分支不会回答“文字何时刷新”。反过来，找到设置文字的函数也不能证明它处理了用户点击。

## 用运行时观察确认路径

静态分析给出候选路径；运行时观察用目标进程的实际消息、窗口和状态变化确认候选。

- 点击控件一次，记录命中的消息、参数、父窗口、控件句柄和调用栈。
- 观察文字变化时，在目标文本写入或绘制路径上停下，记录控件身份、输入文本和触发调用栈。
- 对自绘界面，观察命中测试结果、选中的动作分支和后续状态变化。
- 检查调试器的条件断点是否真的会暂停。热路径上的无条件断点可能产生大量停顿；优先选择与目标窗口或事件关联的代码点。
- 将“找到字符串”“静态调用链成立”“运行时命中”和“界面结果已观察”分开记录。断点命中只证明执行到该位置。

## 输出可复核的分析记录

把控件身份、候选路径和证据层级写在一起，读者才能复查结论适用于哪个目标。

- **目标与范围**：目标文件的本地指纹、界面上下文、要追踪的交互或刷新行为。
- **控件身份**：父窗口、控件类、控件标识符或运行时句柄，以及这些值的来源。
- **静态路径**：创建回调、消息类型、参数解释、分发逻辑、处理函数和最终消费者。
- **运行时证据**：触发步骤、断点位置、实际参数、调用栈和可见结果。
- **未决事项**：尚未确认的框架、自绘分支、条件门控或未覆盖输入。

不要把某个构建的地址、偏移或控件编号写成跨版本常量。需要分享样本结论时，标清目标范围，并提示读者在自己的副本上复核。
