# 特技桩函数：还原调用参数

> **适用范围**：桩函数的形式和参数含义会随引擎构建与调用点变化。以下模板用于阅读汇编；尖括号内容是占位符，不是可直接应用的补丁。

## 桩函数的作用

桩函数通常是连接游戏逻辑与判定处理函数的小型包装。它可能压入若干参数、调用调度函数，并处理返回值或栈空间。桩函数不一定一项特技对应一个，也不保证固定地址或固定字节长度。

## 从 `push` 还原参数

下面的示意按一个分析样本中看到的压栈顺序书写。调用者先压入的值会排在较高的栈地址；被调用函数常在建立栈帧后通过 `[ebp+8]`、`[ebp+0xC]` 等位置读取参数。

```asm
push <effect_mode>
push <combine_mode>
push <equipment_effect_id>
push <personal_effect_id>
call <dispatcher>
```

这些名称只是便于追踪的标签。请沿调用链确认每个值在哪里读取、如何转换，以及最终影响哪个判断或计算。不要只看 `push` 数值或相邻特技的注释来确定字段含义。

## 两类常见调用形态

- **经调度函数调用**：桩函数把参数交给调度函数；调度函数可能先做表查询，再调用核心处理函数。
- **直接调用处理函数**：调用点绕过某些调度步骤。它可能有不同的前置条件和返回值语义，不能默认等同于经调度的路径。

识别形态时，记录实际 `call` 目标、被调用者的栈清理方式，以及调用者如何使用返回值。`ret N` 与调用者的 `add esp, N` 也要结合起来看，确认参数由哪一侧清理。

## 校对桩函数说明的检查表

1. 从调用点向后解码完整指令，确认函数边界和所有分支。
2. 按压栈顺序还原参数，并逐一核对被调用者的读取位置。
3. 检查调用前是否设置 `ECX`、`EDX` 或其他寄存器。
4. 继续追踪被调用函数和返回值消费者，不用桩函数的注释替代调用链证据。
5. 若结论涉及实际游戏效果，在目标引擎及对应数据配置下单独验证。
