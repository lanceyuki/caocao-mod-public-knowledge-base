# 从需求到可复核结果：二进制引擎开发方法总览

本页是候选知识库的阅读入口，串联功能开发 skill、动态调试方法和样本机制案例。具体操作步骤以各自页面为准。

> 本知识库中的引擎分析内容基于 6.5pl 样本整理，不保证绝对正确或适用于所有引擎。样本地址、偏移和调用关系只作复查线索，使用者应在自己的目标上重新定位和验证。

## 一条完整的开发路径

问题与目标 → 行为契约与验收场景 → 追踪目标代码和数据直到相关消费者 → 最小且可回滚的改动 → 按风险分层验证 → 记录结论、证据和未决边界

### 1. 先界定问题

确定本次要回答的问题、目标构建、允许修改的行为和验收结果。保存干净基线与回滚材料；调试崩溃时先保留失败现场。

把游戏说明、既有行为或需求写成短的行为契约：触发条件、对象、输入、预期结果、应保留的原生分支，以及要覆盖的边界场景。说明文本提供语义线索，目标代码流负责核对具体实现。

### 2. 沿代码流追到结果

从与问题直接相关的输入或判断出发，按需追踪：

读取 → 选择或计算 → 后续修饰 → 写入或返回 → 实际消费者

区分数据记录、战场运行时对象、事务数据、共享状态和调用帧局部值。名称相似或地址相邻，不能证明它们是同一个对象或字段。检查每个分支如何设置返回值，以及调用者如何比较、累加或继续传递该值。

研究范围应覆盖行为契约要求的路径，并追到足以回答问题的消费者。相邻功能只有在契约依赖它时才扩展分析。

### 3. 只在需要时增加动态证据

| 要证明的内容 | 对应证据 |
|---|---|
| 函数边界、调用关系、参数位置、条件跳转方向 | 对目标样本的静态分析 |
| 某次运行中实际经过的分支、对象指针和值 | 运行时观察与内存读回 |
| 修改后的文件是否包含预期字节 | 文件写入后的重新读取与逐字节比较 |
| 程序是否能启动、修改路径是否执行 | 受控启动与路径观察 |
| 玩家实际看到或体验到的效果 | 对应场景下的游戏内验收 |

证据层级各自回答不同问题。断点命中只证明执行到该位置；内存读回只证明该次运行的瞬时状态；启动成功不等于玩法效果正确。应针对仍未解决的具体问题选择观察点，并记录未覆盖路径。

### 4. 做最小且可恢复的改动

实现前核对目标字节、指令边界、所有相关分支、调用约定、寄存器和栈行为。设计时说明为什么选该位置、覆盖哪些路径、哪些原生行为必须保留，以及怎样回滚。

让补丁从单一生成源产生。按最终字节重新检查长度、跳转目标和写入范围；验证应用后的磁盘文件，而不是只检查生成器的中间输出。

### 5. 按改动风险验证

逐项报告静态检查、文件读回、运行时读回、受控启动、路径观察和游戏内结果。只报告实际完成的层级。

组合已分别验证的功能时，保留各自独立验收证据，再检查组合是否改变共享写入、共用调用路径或状态交互。集成没有改变某条功能路径时，不把未执行的全量玩法矩阵写成已验收；集成本身改变了行为时，验证受影响的场景。

### 6. 把结论写成可复查资料

每条知识至少说明：

- 研究问题与目标样本范围；
- 对象、字段和输入值的来源；
- 从输入到消费者的静态路径；
- 哪些结论由静态分析、运行时读回或实际玩法支持；
- 未覆盖的路径、未知语义和读者的复核方法。

把可复用方法与样本事实分开。不要把单个样本的地址、偏移或编号写成跨构建常量；不要把未完成的动态或游戏内验收写成已确认结果。

### 7. 从项目记录提炼可分享知识

项目记录用于还原工作过程；公共知识库应保留读者可以复用的方法和有证据支持的有限结论，不直接复制开发时间线或调试流水。整理每条候选内容时，逐项写明：

- **目标与范围**：要回答的问题、适用样本或条件，以及结论不覆盖的对象；
- **证据**：静态分析、运行时读回、受控启动或实际场景验收分别支持什么，只写实际取得的证据；
- **未知边界**：尚未追踪的分支、未验证的结果和不能推广的范围；
- **来源**：结论来自哪些工作记录、代码或公开资料，并区分自己的归纳与引用材料。

整理后按[公共文件清单](../PUBLIC-MANIFEST.md)逐项核对实际文件，只发布清单列出的内容；再检查候选包更新日志是否准确说明新增知识、证据类型和保留边界。工作过程留在内部记录中，不能因为结论已提炼就把原始记录、引擎文件或资产一并带入候选包。
